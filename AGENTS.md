# AGENTS.md — NullRelay Card Game

## Purpose

This repository implements the original **NullRelay** tactical board/card game. Read **[GAME_DESIGN.md](GAME_DESIGN.md)** *before* planning or changing gameplay. This file tells future human/AI contributors how to preserve the design; GAME_DESIGN.md is the canonical game specification.

This project is **in the design / pre-implementation phase**. The initial implementation is intended to be playable with **P1 human, P2–P4 AI**, plus a hostile station AI faction; multiplayer can follow. The user owns game-design decisions.

## Non-negotiable collaboration rules

1. **Do not invent or silently 'fix' gameplay rules.** Preserve everything marked **LOCKED** in GAME_DESIGN.md. Treat **PROVISIONAL** values as defaults suitable for balancing, not immutable constants. Treat **OPEN** items as questions, not permission to decide.
2. **Ask before changing mechanics.** If implementation cannot proceed without an open decision, make the smallest possible isolated assumption, label it clearly **temporary / not approved**, and expose it via configuration or TODO; prefer asking the owner first.
3. **Preserve phase ordering:** Start one Process → Update one Process → Mod one location → Activate. For players, Activate selects one Process; for the station (LOCKED v3.8), Activate permits each deployed hostile Process one activation. Start/Update/Mod are each optional, at most once per turn/Station Phase, and must remain in order. Commands and eligible Operator abilities never reorder the slots.
4. **Favor a pure deterministic game-rules core** independent of rendering, network, persistence or AI. UI should issue legal action intents and display the authoritative resulting state; it must not calculate ownership, damage, resources, or rule legality by itself.
5. **Do not hardcode 'current' balance defaults** throughout the engine. Use board/config rules for grid dimensions, starting resources and income cap; card data for printed stats and costs.
6. **Keep precise zone semantics:** Discard and Graveyard are distinct. Process discarded from hand is not the same as Process destroyed on board. Attached Updates must be cleaned up.
7. **Do not overwrite work belonging to another contributor.** Inspect the branch/diff, use focused commits, and explain breaking changes. No implicit force pushes or deletion of unrelated files.
8. **Keep documentation synchronized.** When the user approves a new rule, edit GAME_DESIGN.md in the same change as any related code/tests. Record unresolved questions rather than concealing them.

## Canonical baseline in brief

- Standard map: **9×9**, orthogonal connection graph. Player Injection Points at the four edge midpoints; hostile station Injection Point at center. Only Processes occupy cells; maximum one Process per cell and one Module per location.
- **End-of-owner-turn** occupation captures territory; ownership persists after departure. Capture a player's Injection Point to eliminate them; the hostile center cannot be captured normally. **LOCKED v3.9–v3.10:** the station's initial spawn is its central Injection Point (4,4); a player-controlled spawn reclaimed by a station Process at Station Phase end becomes **Open** and automatically station-eligible for future Starts **once empty**, preserving the spawn location type. A still-occupying station Process blocks deployment; no retroactive Start is allowed. Ordinary Open cells do **not** become spawn locations merely because they are Open. **Open locations economically belong to the station, not to a fifth player.** At the **end of the Station Phase**, each location occupied by a station Process becomes **Open**, removing any player's control and discarding a replaced/removed Module. Eliminated players' territory becomes Open.
- **Station card parity (LOCKED v3.12):** Updates, Modules and Commands use the **same engine validation, targeting, costs, stack/timing, zone transitions and play limits** for the station as for human/AI players. Station Updates attach to its own Processes using its one Update slot; station Modules use its one Mod slot and treat Open locations as controlled; station Commands are fully reactive, including on other players' turns, with no special station-only timing or exemptions. Do not clone separate station-only implementations of these card types.
- **Same-name non-stacking (LOCKED v3.24):** multiple Updates or Modules sharing a **card name** do not combine their effects on the **same target**. Preserve one-Update-per-Process, one-Module-per-location, and max-3-copies-in-deck rules. Multiple copies can exist on different targets; do not silently prohibit duplicate names across the entire board. **LOCKED v3.25:** overlapping sources of a **same-named continuous ability** count only once on a target (e.g., two DEFENSE GRID Modules granting +1 Integrity within range 2 yield +1, never +2). If one source ceases applying, another still maintains the benefit. Recompute eligibility from currently active sources; do not pick a permanent 'winning' Module. **LOCKED v3.26:** same-named triggered abilities from multiple applicable sources produce **only one trigger per affected target and event** (e.g., two COUNTERMEASURE Modules covering a Process damaged once retaliate for 1 total damage, not 2). This is keyed by named ability/affected target/event, not by card instance; separate targets or separate events can trigger normally. **LOCKED v3.27:** where the same named ability applies at multiple numeric strengths, apply **the highest eligible value only** for continuous or triggered effects; e.g., COUNTERMEASURE 1 + COUNTERMEASURE 2 deals 2 total, not 3, from one qualifying event. If the higher-strength source disappears, use the strongest remaining source. Ability strength numerals are not different ability names. **LOCKED v3.28:** differently named abilities **stack by default**, even if they modify the same stat/target; e.g., ARMOR 2 + FORTIFY 1 provide +3 if both card effects increase that stat. Explicit card text may prohibit or override stacking. Existing same-named ability suppression/highest-value handling remains intact. **OPEN:** differing nonnumeric wording/incomparable effects of the same named ability.
- **Station Modules (LOCKED v3.11):** the station may Mod **any Open location**, whether occupied or empty, using its one paid Mod action per Station Phase, just as players may Mod any location they control. Never require a station Process to occupy it; never permit Mod on player-controlled locations without an explicit card effect. Player capture of an Open location discards its station Module.
- **Station phase (LOCKED v3.0):** after every surviving player has taken a turn, the hostile station faction acts in its own once-per-round phase, then the round ends. All hostile deployed forces belong to the station; the station does not occupy a position in randomized player order. **Every deployed hostile Process may activate once per Station phase (reaffirmed and LOCKED v3.5)**. The station plays its **own deck and resources** using the same card rules as players; escalation irreversibly increases its **draw-to hand-size target** from **4 → 5 → 6**, with **7** planned for an as-yet-undefined additional trigger. It does **not** automatically deploy a force of 3/5/6+ Processes on escalation. **Inward progress from starting edges** is LOCKED, and **dotted escalation-zone boundaries must be shown on the board**. **LOCKED (v3.3):** for the standard 9×9 board, Tier 1 begins in the inclusive central **5×5 square** (zero-based rows and columns **2…6**); Tier 2 begins in the central **3×3 square** (rows and columns **3…5**). **Any player's Process reaching a zone triggers it**; escalation never recedes. The two nested square perimeters are drawn as **dotted lines**, exactly as in the approved board diagram. A boundary cell counts as inside. For other boards, configure explicit zone geometry; do not use remaining distance-to-center or the superseded 3/6 step suggestions.
- 30 cards/deck; max 3 copies of a card; 1 Operator outside deck. Player starting hand 4; at each round start optionally discard any number and draw **up to 4**, no hand limit. The station instead draws up to its escalating **4/5/6** target (eventual 7 trigger OPEN). Draw pile reshuffles from Discard when exhausted; Graveyard stays separate.
- **Player** round-start income **1 per owned cell, max 5 *income per round***, stored resources uncapped. Standard player starting bank 2; initial owned Injection Point yields 1 on round 1. **Station** begins with **0 banked resources (LOCKED v3.7)** and gains ordinary income in round 1 before its first Station Phase; its income depends on Open cells, with a **LOCKED minimum 2/round** and **PROVISIONAL** formula `max(2, min(5, ceil(openCells / 15)))`; don't mistake the provisional formula/cap for approved final balance. Accumulated station resources are not capped.
- Each player activates **one** Process per turn. Slow/Normal/Fast all Move at most one edge; Slow cannot Move on deployment round or after moving previous round, Normal cannot Move on deployment round, Fast can.
- Process Attack is a **single stat**; damage persists. Entering an enemy-occupied connected neighboring cell initiates simultaneous melee. Shooting allows simultaneous retaliation only if defender can reach shooter.
- Operator has exactly one passive and one activated ability; activated ability at most once/round and does not consume a fixed action. **Activated abilities are restricted to their Operator owner's turn (LOCKED v2.9); reactive off-turn play belongs to Commands.** **LOCKED v3.13:** the station has one **Station Operator** card, distinct from player/AI Player Operators, with station-specific abilities. A Station Operator's activated ability is owner-turn-only, meaning **during the Station Phase**, and uses the same once-per-round/zero-action-slot Operator framework.
- Commands can be used during anyone's turn, as responses, globally by default; paid on play, LIFO response resolution, canceled Commands go to Discard. Some detailed priority rules remain open.
- **Triggered ability timing (LOCKED v3.18):** triggers from Operators, Processes, Updates, Modules and triggered Command text **fire and resolve when their conditions occur**, unless the card explicitly says otherwise. Triggered card effects may override ordinary action timing/limits only as printed (e.g., REPLACE can install an extra paid Module without consuming the normal Mod slot). **LOCKED v3.19:** simultaneous triggers from the same event resolve automatically: the active faction first, then player factions in established initiative order wrapping from the active player; during Station Phase the station is active and resolves first, followed by players in fixed initiative order. Resolve each effect fully before the next. **LOCKED v3.20:** during player turns, resolve station triggers **last**, after all player factions in wrapped initiative order; during Station Phase, station triggers resolve **first**. **LOCKED v3.21:** for simultaneous triggers from board-associated sources belonging to the **same faction**, use board order (ascending row, then column: top-left to bottom-right). Process/Update effects use their Process location; Module effects use their location. **LOCKED v3.22:** at the same location, resolve **Process → attached Update → other location effects (e.g. Module)**. Resolve **off-board Operator triggers after all board-associated triggers of that faction**. **LOCKED v3.23:** when resolving a trigger produces new trigger(s), resolve those immediately (recursively) before returning to pending triggers from the original event; use existing priority/order rules for simultaneously generated triggers. **LOCKED v3.24:** each triggered ability **instance** fires at most once per **original event**, including within nested chains; independent later events can trigger it again. Preserve the originating event ID through recursive triggers. **OPEN:** multiple effects tied within the same category, other off-board effects, and Command response interactions.
- Provisional scoring: +1/owned cell at end of player's turn; +1/per boss damage; +50 to surviving player with largest total contribution when boss is destroyed.

Refer to GAME_DESIGN.md for important exceptions and definitions. This summary is intentionally insufficient as an implementation spec.

**Narrative guardrail:** NOXENGINE and VOIDSYNC are intentionally mysterious, not confirmed enemies. Do not use either as a default Station Operator, assign villain status, or reveal their allegiance. Station Operator names should read like terminal operations or processes and suggest their mechanics. **`REMOVE/REPLACE` is the first approved Station Operator identity (LOCKED v3.14)**, with a thematic focus on overwriting/replacing infrastructure. **LOCKED v3.15:** Passive **REPLACE** may install a paid Module from station hand on a newly reclaimed Open location whose player Module was discarded; each qualifying location is a separate optional trigger that **fires and resolves when reclamation occurs**, during end-of-Station-Phase cleanup, before the phase ends. Its paid installation does **not** consume the one normal Mod slot; normal Mod plus one or more REPLACE-triggered Modules may be installed in one phase. This is a **card effect overriding ordinary action timing**, not permission for extra ordinary Mods. Activated **REMOVE**, once per Station Phase, destroys an enemy Module by paying resources equal to that Module's printed cost; it does not consume a fixed action. **LOCKED v3.16:** REMOVE can target an enemy Module **only on a connected orthogonally adjacent location to at least one deployed station Process** (not diagonal, not the Process's own location, and not global). `KILL/ERASE`, `SCAN/TRACE`, etc. are only name candidates, not approved card definitions.

## Suggested architecture (guidance, not a mandated framework)

Define concepts explicitly:
- **GameState:** players, turn order, round, current player/phase, ruleset, board graph, pending Command stack, station faction with its own card zones/resources and persistent escalation tier, score, event history.
- **Board/Location:** stable ID, row/column, graph edges, type, owner, occupying Process ID, optional Module ID.
- **PlayerState:** Operator, banked resources, hand/deck/Discard/Graveyard, eliminated flag, per-match boss contribution, action-slot completion and per-round ability usage. Operator definitions should have an eligibility subtype (`station` or `player`) so station-only Operators cannot be selected by human/AI player factions, without requiring a separate engine class.
- **Card definitions vs instances:** immutable printed definitions and stable instance IDs for damage, attachments, temporary status and provenance. Card effects should be testable without UI.
- **Action intents:** explicit typed inputs to an authoritative validator/resolver (start, update, mod, move/melee, shoot, ability, pass, Command, Command response, pass priority, end step).
- **Events:** deterministic outputs usable by UI, logging, AI planning, replay and tests (damage dealt, card moved, capture, elimination, income, score, stack push/resolve, etc.).
- **RNG:** seedable and isolated for deck shuffles and initially randomized turn order. Keep the randomized player order fixed after setup.
- **AI:** consumes the same state/legality/action API as the human client; never bypasses costs, range, step sequence or information boundaries.

Do not implement a speculative networking layer or large content system before the core rules are verified.

## Rules-engine invariants and test priorities

Write tests at the rule layer. Cover at minimum:

1. **Board setup:** 9×9, four edge Injection Points and one center enemy objective; links orthogonal by default; occupancy max one.
2. **Turn phases:** round-start discard/draw/income order; player turns in fixed randomized order; exactly four optional action slots in fixed sequence; at most one player Process activates; **one station phase after all player turns**. **Station exception LOCKED v3.8:** its phase uses ordered slots **Start up to one Process → Update up to one Process → Mod up to one location → activate each deployed hostile Process up to once**. Start/Update/Mod are each at most once for the *whole Station Phase*, not once per Process. Apply ordinary costs, legality and individual Process movement cooldowns. Escalation tiers only rise; store the highest attained tier.
3. **Economy:** player income cap applies to *income*, not storage. Resources bank across turns; 2 initial + 1 first-round income for the standard player. Station starts at 0 banked resources, then gains round-1 income before its first Station Phase. Station income has floor 2 per round, provisional scaling with Open cell count and no storage cap. Captures/reclamation do not retroactively modify this round's income.
4. **Spawn/ownership:** deployment only at empty appropriate spawns, end-turn player capture, end-of-Station-Phase reclamation to Open at station-occupied cells, persistent ownership elsewhere, Modules destroyed on control change, elimination makes territory Open. The station's central Injection Point (4,4) is its starting spawn. It may later deploy at other empty Open **spawn** locations, not at ordinary Open cells. Test occupied center spawn, Open non-spawn corridors, reclaimed spawn locations retaining spawn kind, reclaimed-but-occupied spawn not yet deployable, later vacated reclaimed spawn deployable, player-controlled spawns, and one-Start-per-Station-Phase limit.
5. **Movement:** each type's deployment-round eligibility, Slow previous-round cooldown including blocked melee moves, exactly one graph edge of movement.
6. **Combat:** simultaneous attacks; ranged retaliation only in range; persistent damage; no defense stat; both-dead melee stays empty and location ownership unchanged.
7. **Zones:** hand-discarded Process → Discard; destroyed board Process → Graveyard; Update → Discard; replacement cleanup; reshuffle excludes Graveyard.
7a. **Non-stacking named abilities:** test two DEFENSE GRID Modules overlapping a Process yield exactly +1 Integrity, losing one source retains +1, losing both removes +1, and multiple sources with a matching ability name do not stack the same continuous benefit. Distinct named effects stack by default unless explicit card text says otherwise. Test ARMOR 2 + FORTIFY 1 supplying a combined +3 to the same affected stat, and a printed non-stacking exception. Preserve legal duplicate copies on separate board locations and the existing single-attachment slots. Test two COUNTERMEASURE Modules covering one Process generate exactly one retaliation on one damage event, while separate damage events or separately affected Processes can trigger independently. Test COUNTERMEASURE 1 and 2 jointly producing one trigger for 2 damage (never 3), and falling back to 1 when the stronger source leaves. Test continuous +1/+2 same-name overlap uses +2, not +3. Do not invent precedence between same-named abilities with incomparable wording.
8. **Commands:** any-turn play, LIFO nested responses, paid-before-resolution, canceled Commands to Discard, global default targeting with card exceptions.
8a. **Triggered abilities:** test immediate trigger resolution on each relevant card type, exceptions with printed delayed timing, card effects overriding only specified normal action restrictions, and no accidental action-slot consumption. Test active-first priority, wraparound in fixed player initiative, **station-last during player turns**, and **station-first in Station Phase**. Test two same-faction triggers from different cells resolve by ascending row then column, regardless of deployment order. Test same-cell Process-before-Update-before-Module ordering and Operator-after-board ordering regardless of card deployment/attachment order. Test nested/chained triggers resolving before the remaining original-event triggers, recursive chains, and simultaneous new triggers using established priority. Do not invent ordering of tied effects in the same category, other off-board effects, per-original-event loop handling, or interactions with an unresolved Command stack. Test A→B→A trigger loops (A fires only once for that original event), and fresh later events triggering A again. Verify **station Commands** are legal during player turns and use identical timing/stack/cost rules.
9. **Station card parity:** station Update/Mod/Command legality must be identical to players, except that Open locations count as controlled for station Modules. Test legal and illegal target/attachment cases, one Update and Mod per phase, replacements and costs, reactive station Commands, and no extra plays from per-Process activations.
9. **Operator abilities:** passive effects disabled upon elimination, once-per-round activated usage, not consuming fixed actions; **owner-turn-only is confirmed; reject off-turn Operator activations**.
10. **Station Operators:** `REMOVE/REPLACE` is the first approved Station Operator. Test Station Operator eligibility, once-per-Station-Phase activated ability use, and no fixed-action-slot consumption. For passive **REPLACE**, test reclamation of a player Module, the removed Module going to its owner's Discard, optional paid replacement from station hand on the now-Open location, legal Module placement, no resource/hand card available, no trigger for an empty location or one without an enemy Module, immediate on-trigger resolution before Station Phase end, coexistence of a normal Mod plus one REPLACE installation in the same phase, multiple paid triggers for separate reclaimed locations, and preservation of the normal Mod action limit. For activated **REMOVE**, test destroying enemy Modules and moving them to Discard after paying their **printed** variable cost (including insufficient resources), and once-per-round use. Test REMOVE with an adjacent Module, diagonal Module, remote Module, same-cell Module, and a geometrically adjacent but disconnected location; only a connected orthogonal neighbor is eligible.
10. **Station Module placement:** test legal Mod on distant, empty Open locations; refusal on player-controlled locations; only one Mod per phase; paid costs; Module removal when a player captures Open territory.
11. **Station action slots / activation exception:** station may Start at most one Process, Update at most one Process and Mod at most one location in that order per Station Phase; then each deployed hostile Process gets up to one legal activation. Never cap total station activations at one or allow multiple Starts/Updates/Mods just because there are multiple hostile Processes. Test station phases with 0, 1 and multiple deployed Processes, and illegal second Start/Update/Mod attempts.
11. **Station escalation:** station has its own deck/resources and regular draw-to target **4 initially, 5 at Tier 1, 6 at Tier 2**; a future 7-card tier lacks a trigger. Escalation does **not** force-spawn Processes or immediately draw cards. Standard board: entering both row and column ranges **2…6** reaches Tier 1; **3…5** reaches Tier 2. UI displays **dotted square zone boundaries**, separately from graph links. Test inclusive boundaries, direct Tier 2 entry, retreat/death, monotonicity, draw-to without hard hand cap, and no spawning on escalation.
12. **Station reclamation/economy:** test that station starts at exactly 0 resources, receives its normal round-1 income before its first Station Phase, and receives no extra setup grant; Open is a station economic state; any surviving station Process occupying a player-controlled location when the Station Phase ends returns it to Open and destroys its Module. Test empty locations remaining controlled, destroyed station Processes not reclaiming, late-phase reclaim income applying next round, minimum 2 income, and provisional formula boundaries.
13. **Scoring:** boss damage accumulated per player throughout match; only surviving top contributor receives provisional +50; territory points at end of player's turn.

Add regression tests before fixing a bug. For every new mechanic, test both an ordinary case and at least one counterexample.

## Documentation and design-change process

For a new decision:
1. Identify the relevant **OPEN** item or affected **LOCKED** rule.
2. Have the owner explicitly agree; if it changes a locked rule, call out the change.
3. Update GAME_DESIGN.md and this file if an implementation invariant changes.
4. Add or update tests before merging behavior changes.
5. Summarize the gameplay impact in the commit or PR.

Use concise, legible Markdown and specific examples. Prefer stable terminology (**Operator, Process, Command, Update, Module, Injection Point, Integrity, Attack, Range, Slow/Normal/Fast, Discard, Graveyard**).

## Scope / initial development priorities

1. Data model and seedable deterministic simulation, including board graph and card-zone management.
2. Setup, turn/round transitions, legality checks, resource bank and territory control.
3. Process deployment, activation, movement, melee, shooting and destruction.
4. Fixed action slots, Updates and Modules, then Commands and stack/priority.
5. Operator passive/activated effects with owner-turn-only activated timing and Station Operator eligibility rules; defer specific station abilities until designed.
6. Station-faction card-driven action policy, detailed ordering of hostile activations, third escalation threshold, central objective and scoring once unresolved detailed rules are agreed.
7. Playable single-player UI and AI opponents using the same rules interface; future multiplayer.

These are suggested implementation milestones, **not permission to decide open gameplay rules**.
